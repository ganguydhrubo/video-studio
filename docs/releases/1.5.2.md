## Takebloom 1.5.2 — file chooser and connection fix

The blocking server-side Windows dialog has been removed. It could open invisibly and leave browser requests waiting. Multiple clicks could occupy the browser's available connections, causing unrelated System-page requests to time out despite a responsive server.

- Browse files is now a real browser file input that receives the user gesture directly, without waiting for an HTTP request or a separate PowerShell process.
- A separate file-path option reads a chosen local video directly without copying. Its endpoint validates the file and returns immediately; it opens no dialog.
- The old picker endpoint fails promptly with a migration message rather than holding a connection.
- Small API requests have a timeout and clear recovery text. Large local video transfers use a separate streaming endpoint and retain no fixed file-size cap.
- The light theme, logo, cinematic opening, local preview and existing projects are preserved.

Tests cover the retired picker, direct Unicode paths, bounded-memory 113 MiB copying, interrupted-copy cleanup and selected-file media access. Actual interactive GUI clicking could not be automated under the saved browser permissions; the file input now uses the browser's standard interaction rather than the unverified background dialog.
