## Takebloom 1.6.0 — cinematic light workspace

The interface is redesigned around the original animated world. The editing engine, project format, upload architecture and local security checks are unchanged.

- **Opening.** A 3-second branded opening with the animated world, a Skip button, keyboard skip and a replay button. It plays once per session and never when Windows is set to reduce motion. It resolves into the light workspace with an iris transition.
- **Light workspace.** Warm ivory surfaces with deep teal, coral and restrained violet. The animated world now lives inside cinema-style screens at the top of each page, so text and controls stay on clear light surfaces.
- **Create.** Three real steps (choose footage, describe the edit, create the draft) light up only from what is on the form. Each clip shows its name, size, real byte progress, Ready state, Try again and Remove. The source preview is labelled as the original, not the edit.
- **Editing.** Each real stage has its own illustrated vignette, a friendly headline, elapsed time, a stage path and milestones that are earned only when the engine marks a stage done. There are no percentages, time guesses or invented scores. Stop asks first and keeps finished work.
- **Results.** The finished video leads, with a credits strip of earned milestones, transcript review, timeline, re-edit controls, local exports and feedback.
- **Projects.** Cards show thumbnails and real states: editing now, completed, stopped (can continue) or needs attention. Continue editing resumes from the first unfinished stage. Reopening a running project reconnects to its job.
- **AI editor.** OpenCode, Claude, OpenAI Codex, Gemini, Qwen and Ollama cards show four separate facts: installed, signed in, still checking, and proven in one of your finished edits. A sign-in alone is never shown as proof that the service answers.
- **Errors.** Raw browser and engine messages are replaced with plain recovery text. Clips and typed text are kept. Technical details stay collapsed.
- **Lightness.** The world renders on one small canvas (at most 760 pixels wide), drops to about 8 frames a second while a video is being made and stops when hidden. Status polling is chained so requests cannot overlap, and each System card loads on its own.

New server pieces: a `resume` action on the existing refine route (continues an interrupted project, one job per project) and a route that serves the bundled Instrument Serif font. `/api/pick-files` remains retired.

Tests: 55 Python tests and the file-input test pass. The interface was exercised in a browser against the real local server with a simulated engine. A full edit with the real engine, the packaged app and a click through the Windows file chooser were not run before this release was prepared; see KNOWN_LIMITATIONS.
